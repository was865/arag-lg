# 029 回答の流れを明示のグラフにし、実行の経路を見せる — 要件

状態: **着手（P0〜P2・P3 の T14）**。ブランチ `feat/explicit-graph`。

## なぜやるか

- 今の流れ（理解 → 最初の検索 → モデルの調査 → 確認 → 引用の整理 → 続けて聞く）は、`create_agent` の middleware の中に手続きとして書いてある。`AgentPolicyMiddleware.awrap_model_call` の 1 つの関数に、確認の差し戻し・空の生成のやり直し・書き直しの取り消しが重なり、分岐を追いにくい。026 以降の不具合の多く（差し戻しへの返事が回答になる、確認が正しい答えを壊す）はここで起きた。
- 構成図（`docs/architecture.html`）は手書きで、実装とずれている（2026-11-13 時点で旧モデルの構成のまま）。
- 「詳細」のステップの一覧は時系列の記録で、**どの分岐を通ったか**（確認で戻ったのか、退避したのか）は一覧を読んで推し量るしかない。

LangGraph の強みのうち、この製品で実際に効くのは次の 3 つと判断した: (1) 流れを節点と辺で書けること、(2) その図をコードから生成できること、(3) 節点ごとの状態を checkpoint に残せること。

## 採らないもの（理由つき）

- **LangGraph Studio / `langgraph dev`**: 動かすのに `langgraph-api`（Elastic License 2.0）と LangSmith への接続が要る。`AGENTS.md` のライセンスの基準（ELv2 不可・外部接続の要るものは不可）に反する。図と経路の表示は自前で作る（下の R5〜R9）。着手時にライセンスを確かめ直す（T1）。
- **`interrupt` での聞き返し**: この製品は 1 つの質問が 1 つの run で、会話の履歴が次の run に渡る。聞き返しは「選択肢つきの回答で終わるターン」として普通の run で書ける（R10〜R12）。`interrupt` は run を止めたまま待つので、runner のキュー・タイムアウト・取消・再生成のすべてに「待機中」の扱いを足すことになり、得るものに見合わない。途中で人の承認が要る操作（書き込み・送信）を持つようになったら見直す。

## 1. 明示のグラフ（挙動は変えない）

- R1. 回答の流れを LangGraph の `StateGraph` として書く。節点は「画像の読み取り・質問の理解・最初の検索・調査（モデルと道具の輪）・確認・回答の確定・続けて聞く」。分岐（雑談は検索を飛ばす／確認で調査へ戻る／空の生成でやり直す／下書きへ退避する）は条件つきの辺として書く。
- R2. 作り直しの前後で、偽モデルのテスト（`test_agent_graph.py` ほか）の期待と、harukaze_mix 69 題の指標が変わらないこと（指標は ±0.01、`wrong_fact` は 0 のまま）。記録されるステップの種類・順序・中身も変わらないこと。
- R3. 「後端の動きはすべて記録に出す」を保つ。加えて、各ステップに、それを出した節点の名前を持たせる。
- R4. 確認の規則（調べ残し・表・数字、それぞれ 1 ターンに 1 度まで）と保護（空の生成・書き直しの取り消し）は、節点と辺の上で読める形にする（1 つの関数の中の入れ子にしない）。

## 2. 図をコードから作る

- R5. `make graph` で、グラフの定義から図（Mermaid）を `docs/agent-graph.md` に書き出す。CI は、書き出した図がコミット済みのものと一致することを確かめる（`gen-check` と同じ流儀）。
- R6. `docs/architecture.html` の「回答の流れ」は、この図を参照する形に改め、手書きの流れ図を持たない。あわせて全体の構成（モデル・ポート）を今の実装に合わせ、IP アドレスを消す。

## 3. 実行の経路を見せる

- R7. 回答の「詳細」に「流れ」の表示を足す。この回答が実際にたどった順に段階を並べ、差し戻しの後の調査・確認は「2 周目」として続けて並べる（回数でまとめない）。各段階には、何をしたか（差し戻しなら理由）と所要時間を出し、いつもと違う経路（差し戻し・下書きへの退避・雑談）だけをひと言で要約する（T30 で変更。そのまま通過した回答と実行中は要約を出さない）。段階の名前には、その段階の説明をホバーで添える。確認を通したことも記録に残す。
- R8. 段階を押すと、その段階（周回ごと）が出したステップだけに「詳細」の一覧が絞られる。もう一度押すと戻る。
- R9. 管理画面のフィードバックの詳細にも同じ「流れ」を出す。保存済みの古い回答（節点の名前を持たないステップ）は、ステップの種類から節点を推定して出し、推定であることを示す。

## 4. 聞き返し（任意。1〜3 の後に、別に判断する）

- R10. 質問が、資料の上で複数の対象に当てはまり、対象によって答えが変わるとき（例: 版・機種・拠点が指定されていない）、システムは答える代わりに、対象を選ぶ聞き返しを返してよい。
- R11. 聞き返しは 2〜4 個の選択肢を持ち、選択肢は最初の検索で実際に見つかった対象から作る（資料に無い選択肢を作らない）。利用者は選択肢を押すか、そのまま文で答える。
- R12. 聞き返しは 1 つの質問につき 1 度まで。1 度聞いた後は、あいまいさが残っても、前提を明記して答える。
