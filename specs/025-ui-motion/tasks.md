## 複雑な検索の見直し（2026-11-12、main）

複数の資料を照合する質問（分解手順書の版の違い・品質会議の決定・部品台帳の在庫と単価・合計金額）で確かめた。

- [x] T74 検索の過程の数え方: この版の書式（`<資料 n=… 文書=… 見出し=…>`）と子の検索の hits から、探した文書を数える。探したのに 1 つも引用していない回答は、済みの印でなく「引用なし」の注意として出す
- [x] T75 調べ残しの差し戻し（API の middleware）: 検索が 2 回以下で、下書きが「記載されていない」「不明」「確認が必要」などと認めたら、まだ調べていない種類の資料を探すよう 1 度だけ差し戻す。下書きと依頼は会話の状態（モデルに渡す履歴）には入れないが、差し戻したこと（下書きの全文・きっかけの語・それまでの検索回数・依頼・そのあとの動き）は「調べ残しの見直し」のステップとして記録に残し、「詳細」で見られるようにする（後端の agent・RAG の動きは原則すべて記録に出す）。回答の欄は書き直しで置き換える。実機（Qwen3 8B Thinking）で部品台帳まで探し、合計金額を出典付きで出すようになった
- [x] T76 文書の札の「ほか N 件」を札の形にする（折り返して 1 つだけ次の行に出ても浮かない）。推論を隠していても、考えている間は「考えています…」と出す
- [x] T77 後ろで行う処理も記録に残す（API）: ツールの必須化・呼び出しの上限・前のターンの資料の省略・回答の整形（引用の書き方・資料に無い番号・末尾の言い直し・考えた過程の分離）・会話の要約を、`system` のステップ（`input.kind` で種類）として送り、保存する
- [x] T78 画面では 3 段で深くする: 0 段目は見出しと文書の札、1 段目（「詳細」）はエージェントの段階（検索・読む・計算・見直し）だけ、2 段目は末尾の「システムの処理 N 件」（畳んだまま名前だけ並べる）、3 段目で各処理の入力と出力。生の記録（log 表示）は全部を時刻順に出す
