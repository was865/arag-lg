## 2. 読み方

- **速さ**: 旧版の約 25 分の 1（p50 64 s → 2〜4 s）。ツール呼び出しはほぼ 1 回で、CRAG の書き直しは search 内で済む。
- **引用**: 再現率 0.94〜0.96。落ちるのは主に照合型（cross_doc）で、モデルが 1 回の検索で答え、全文に [1] だけを付けるとき。
  `per_document=3`（1 文書に偏らない検索）で、照合に必要な文書は検索結果には入るようになった（case3 で確認）。
- **事実網羅（ext）が低いのは題集側の要因が大きい**: ext の key_facts は LLM 生成の候補のままで、
  「申請番号: PR-2026-0519」「48時間以内に再測定する」のように文の形で書かれており、正答でも部分一致しない。
  ext は「最終確定はユーザー確認後」の状態なので、評価者側で緩めず、題集の確定時に alias を足す。
- **negative の精度 0** は指標の定義による。根拠の無い題（relevant 空）でも、モデルは「記載がない」と述べるために
  近い資料を引用する。誤りではないので、negative は精度を門禁に使わない。
- **2 回の実行で ±0.05 程度揺れる**（6 題の demo は 1 題で 0.06〜0.17 動く）。門禁は ext の全体値で見る。

## 3. 既定値の決定（E3）

| 項目 | 決定 | 理由 |
|---|---|---|
| `grade_threshold` | 0.3 のまま | ruri reranker は英語の質問×日本語の資料で 0 近くを出すため、英語の質問ではほぼ必ず書き直しが走るが、書き直しは日本語訳を作るので結果は良くなる（en の再現率 0.94〜0.97）。値を振る比較はしていない。 |
| `verify`（根拠検証） | OFF のまま | 忠実度は検証なしで 0.96〜0.98（参考値）。検証は LLM 呼び出しが 1〜2 回増え、p50 が倍近くになる。E2 で評価者を確かめてから再判断する。 |
| `per_document` | 3（新設） | 照合型の質問で、2 番目以降の文書が検索結果から押し出されるのを防ぐ。 |

## 4. 今回直した振る舞い

- `list_documents`（文書名の検索）で内容の語を探して諦める → 名前で見つからなければ search へ誘導。
- 小さいモデルが資料タグをまねた `[n=1]` を書き、引用なしと判定される → `[1]` に正規化。
- 回答にツール名（keyword_search など）が出る → 書かないよう指示。
