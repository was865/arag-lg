# 018 評価用資料の拡充（形式混在・多ターン）— 要件

今の評価用資料（`eval/assets/agentic_rag_demo` の PDF 7 本）は、跨ページ表・図面・複数文件・規則の新旧衝突は押さえているが、
次の能力はまだ測れていない。

- PDF 以外の形式（Word・Excel・PowerPoint）
- 文字の層がない走査 PDF（OCR）
- 英語で書かれた原文（いまは英語の質問はあっても、資料はすべて日本語）
- 似た資料が多いときの取り違え（旧版の手順書、型番違いの仕様書）
- 続けて尋ねる質問（「それの前工程は？」のように、前の質問を踏まえて答える）

架空の会社 1 社分の資料をまとめて作り、新しい題集 `harukaze_mix` で測れるようにする。

- R1 **資料。** 架空の製造業 1 社分の資料を 16 本前後作る。内訳の目安は次のとおり。
  - Word 4 本：規程、手順書（同じ手順書の旧版と改訂版を含む）、議事録
  - Excel 3 本：部品台帳（複数シート・結合セル）、保守記録、価格表
  - PowerPoint 3 本：月次報告、設備紹介、教育資料（本文が少なく図と箇条書きが中心）
  - 文字のある PDF 2 本：仕様書（型番違いの 2 本で、数値だけが違う）
  - 走査 PDF 2 本：文字の層がない画像だけの PDF（点検票、押印のある通知）
  - 英語の資料 2 本：海外拠点の手順書、取引先の仕様書（Word と PDF）

  会社名・人名・型番は架空のものにする。実在の会社・製品と取り違えない名前にする。
- R2 **作り直せること。** 資料は生成スクリプトから毎回同じ内容で作れるようにする（`eval/assets/harukaze_mix/` に、スクリプトと出来上がった資料の両方を置く）。
  生成に使うライブラリは商用利用に制限のないものに限る（`docs/handoff.md` の「授权原则」節）。
- R3 **題。** 60 問前後を作り、種類ごとに `tags` を付ける。
  - 形式ごとの事実（Word・Excel・スライド・走査 PDF・英語資料）：各 4〜6 問
  - 表の読み取り（結合セル、シートをまたぐ参照）
  - 似た資料の取り違え（型番違い・旧版と改訂版の区別）
  - 複数の資料をまたぐ問い（形式をまたぐものを含む）
  - 日英をまたぐ問い（英語資料に日本語で尋ねる、日本語資料に英語で尋ねる）
  - 資料に答えがない題（`expect_no_answer`）：5 問以上
  - 続けて尋ねる題：8 問以上（R4）
- R4 **続けて尋ねる題を測れること。** 題に「前の質問」を並べられるようにする。
  回答評価は、前の質問を同じスレッドで順に尋ねてから最後の質問を採点する。
  検索評価では、最後の質問を書き換えた文（`rewritten`）で測る。
- R5 **確定の手順。** 題の候補は生成スクリプトか LLM で作り、
  利用者が 1 問ずつ確認して確定する（C6 と同じやり方）。確定するまで閾値は置かない。
- R6 **記録。** 確定したら検索評価と回答評価を流し、基準値（baseline）と結果の表（report）を残す。
  形式ごとの事実網羅率を分けて示し、どの形式が弱いかを分かるようにする。

## 対象外（今回はしない）

- 権限の分離（他人の知識ベースが見えないこと）の確認。評価題集ではなく API のテストで扱う。
- 回答評価の採点役を強いモデルに替えること（E2 の続き。DeepSeek の残高が戻ってから）。
- 数百本規模の資料での性能測定。
