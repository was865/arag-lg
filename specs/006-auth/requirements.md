# 006 認証（P4）— 要件

`docs/handoff.md` 第 3 節 P4 の「Better Auth」。完了基準: **登録 → メール確認 → ログイン → チャット・文書ライブラリ → ログアウトがブラウザで通り、ログインしていない利用者は API に一切届かない**。

前提: 認証表は Next（Better Auth）が Postgres の `auth` スキーマに持つ（`specs/000-overview/data-model.md` §2）。Python は Better Auth が発行する JWT を JWKS で検証する（`decisions.md` §6）。UI 文言は日本語のみ。

## 1. 登録・ログイン

- R1. 利用者はメールアドレス・表示名・パスワード（8〜128 文字）で登録できる。最初に登録した利用者は `owner`、以降は `member` になる。
- R2. 利用者はメールアドレスとパスワードでログイン・ログアウトできる。「ログイン状態を保持」を外すとブラウザを閉じた時点でセッションが切れる。保持する場合のセッション期限は 30 日（利用中は延長）。
- R3. ログインの失敗理由（メール未登録・パスワード誤り）は区別せず同じ文言で返す。
- R4. 認証エンドポイントにはレート制限をかける（ログイン・登録・再設定の申請は 1 分あたり数回まで）。超えたら「しばらくしてからお試しください」と表示する。
- R5. BAN された利用者はログインできない（admin プラグイン。BAN の操作 UI は P5）。

## 2. メール確認・パスワード再設定

- R6. 登録時に確認メールを送る。未確認でもログインはできるが、画面上部に確認を促す帯と「確認メールを再送」を出す。
- R7. 未確認の利用者は、質問（run の作成）と文書のアップロードができない（API が 403 `email_not_verified`）。
- R8. 確認リンクを開くと確認済みになり、アプリに戻って「メールアドレスを確認しました」と知らせる。期限切れ・不正なリンクはその旨を出す。
- R9. パスワードを忘れた利用者は再設定メールを申請できる。登録の有無にかかわらず同じ応答を返す（列挙対策）。リンクから新しいパスワードを設定でき、設定後は他のセッションを失効させる。
- R10. メールは SMTP（`ARAG_SMTP_URL`）で送る。開発時は Mailpit。未設定ならサーバのログにリンクを出す（開発専用）。

## 3. アカウント

- R11. ログイン中の利用者は、表示名の変更、パスワードの変更（現在のパスワードが必要。変更時に他のセッションを失効できる）、ログイン中の端末の一覧と個別・他端末すべてのログアウトができる。

## 4. Next と Python の間

- R12. ログインしていない利用者がアプリの画面を開くと `/login?next=<元の URL>` に移り、ログイン後に元の画面へ戻る。ログイン済みで `/login` を開くとアプリへ移る。
- R13. `/api/v1/*` の中継は、セッションから得た JWT を `Authorization: Bearer` で Python に渡す。セッションが無ければ Python を呼ばず 401 を返す。JWT は期限の 1 分前まで使い回す。
- R14. 状態を変える中継要求（GET・HEAD 以外）は `Origin` が自サイトでなければ 403 にする（CSRF 対策）。
- R15. Python（`ARAG_AUTH_MODE=jwt`）は Bearer の JWT を Better Auth の JWKS で検証する（EdDSA、`iss`・`aud`・`exp` を確認）。JWKS はキャッシュし、未知の `kid` のときだけ取り直す（取り直しは 30 秒に 1 回まで）。検証できなければ 401 `unauthenticated`。
- R16. JWT から `sub`（利用者 ID）・`role`・`email`・`email_verified` を使う。未知のロールは `member` とみなす。
- R17. 開発・評価用の利用者ヘッダ（`X-Dev-User-Id`）は `ARAG_AUTH_MODE=dev` のときだけ受け付ける。Web は `ARAG_DEV_USER_ID` を明示したときだけ付ける（既定では付けない）。

## 5. 非機能

- R18. 追加する依存は MIT など商用利用に制限のないもの（`licenses.md` に記録）。Better Auth の有料サービスは使わない。
- R19. 認証表の作成・更新は Web の起動時に自動で行う（`auth` スキーマ。Python の Alembic とは独立）。
