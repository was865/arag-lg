# 036 社内システムの呼び出しを技術者が確かめられる表示 — 要件

状態: 実装済み（2026-11-21）。

「詳細」の社内システム（MCP）の段階は、引数と結果の表しか出していなかった。技術者が次の 3 点を画面で追えるようにする。

- エージェントがどのツールをどの引数で呼んだか
- MCP サーバがその先で何を問い合わせたか（SQL・Odoo の RPC）
- モデルが実際に何を受け取ったか

見た目は今の「詳細」の落ち着いた形を保つ。既定は結果の表で、技術的な中身は切り替えた先に置く。

## 1. 呼び出し

- R1. 社内システムの段階を開くと、呼び出しを 1 行の式（`erp.list_suppliers(term="S-42")`）で出し、写せる。
- R2. 呼び出しの往復の時間（ARag が測る）と、そのうちサーバの中の時間（サーバの trace）を分けて出す。
  サーバの中での問い合わせの回数、10 秒の使い回しかどうか、ERP の利用者（erp_user）も出す。

## 2. 問い合わせ

- R3. MCP サーバは、1 回の呼び出しで発行した問い合わせを trace の `queries` に返す。
  - SQLite（模擬）: 値を埋め込んだ SQL の文。そのまま `sqlite3` で流せる。
  - Odoo: `model.method` と domain・fields・limit などの引数。
  - 各問い合わせに、かかった時間と件数を、分かるときだけ付ける。
- R4. 問い合わせの記録には、合言葉・鍵・利用者の pw を含めない（Odoo の認証の呼び出しは記録しない）。
- R5. 記録は 1 回の呼び出しにつき 30 件・各 4000 字まで。超えた分は数だけを返す。
  使い回し（キャッシュ）の答えは問い合わせを発行していないので、空にして使い回しであることを示す。
- R6. 画面は問い合わせを、種類の札（SQL・Odoo RPC）と等幅の文で出し、1 つずつ写せる。

## 3. MCP とモデル

- R7. 画面は MCP の要求（JSON-RPC の `tools/call`、name と arguments）と、応答の構造（行を除く項目）を JSON で出す。
- R8. モデルに渡した文（表・注記・出典の囲み）を、渡したとおりに出す。

## 4. 見せ方

- R9. 4 つの面（結果・問い合わせ・MCP・モデルに渡した文）を切り替えで出す。既定は結果。
  問い合わせの面には件数を添え、問い合わせの記録が無い（古い記録・模擬でない別のサーバ）ときは出さない。
- R10. 古い記録（新しい項目が無い）も、今までどおり引数と結果で出る。

## 入れないもの

- 画面から SQL を流し直すこと（読み取りでも、任意の文の実行は口を広げすぎる。写して手で流す）。
- 呼び出しの記録の長期の保管（ERP の MCP サーバの監査ログが持つ）。
