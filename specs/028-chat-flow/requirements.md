# 028 会話の動線（続けて聞く・回答の操作の整理・技術者への報告）— 要件

完了基準: **回答のあと 1 クリックで次の質問に進め、回答の下の操作は迷わない数に絞られ、うまくいかなかった回答は過程ごと技術者に届く**。

## 1. 続けて聞く（追問の候補）

- R1. 資料を調べて回答したターンが終わったとき、システムは次に聞きそうな質問を 2〜3 個作り、回答と一緒に保存する。
- R2. 候補は、質問・回答・引用した資料の題名から補助モデルが作る。質問と同じ言語、1 つ 40 字以内（半角は 1 字を半分に数える。英語なら約 80 文字）、単独で意味が通る文（「それ」などを使わない）、今の回答で既に答えた内容を繰り返さない。
- R2a.（T6b で追補）候補は、そのターンで検索に出た資料の抜粋（引用しなかったものも含む）に答えがそのまま書いてある質問だけにする。抜粋から答えられない質問・今の回答に既に書いた値を尋ねる質問は作らない。足りなければ 1〜2 個、無ければ候補なしでよい。
- R2b.（T15 で追補）候補は、このスレッドの直近のターン（今のターンと前の 3 ターン）で既に聞いた質問・既に答えた内容を尋ねない。モデルに直近 3 ターンを渡したうえで、これまでの質問と同じ文、内容の語がすべて会話に出ている候補はシステムが落とし、落とした候補と理由を記録する。
- R3. 雑談（kind=chat）・回答なし（`no_answer_reason` がある）・取消・失敗のターンでは作らない。
- R4. 作るのは回答の本文を流し終えた後。3 秒で打ち切り、失敗・打ち切り・形式の誤りのときは候補なしで終える（回答は遅らせない・失敗させない）。
- R5. 候補を作ったこと（使ったモデル・かかった時間・結果、または失敗の理由）を `system` のステップ（`kind="followups"`）として記録する。
- R6. 画面は、スレッドの**最後の**回答が終わっているときだけ、回答の下に「続けて聞く」と候補を出す。候補を押すと、その文をそのまま送る（入力欄に入れて待たせない）。実行中は出さない。
- R7. 設定 `ARAG_FOLLOWUPS`（既定 true）を false にすると作らない。

## 2. 回答の下の操作

- R8. 回答の下に常に見せる操作は「コピー・再生成・良い・良くない・その他」の 5 つにする。Markdown の保存・HTML の書き出し・時間とトークンは「その他」のメニューに入れる。
- R9. 回答の下の「出典 n 件」の札は出さない（同じ働きが見出しの「出典」と回答の横の「根拠」にある）。

## 3. 表の集計の見せ方

- R10. 「表の集計」のステップの表示は、該当した行・件数・`compute` の列の集計（合計・平均・最大・最小）だけを見せる。ほかの列の集計は「すべての集計」を開いたときに見せる。モデルに渡す文は変えない。

## 4. 技術者への報告（フィードバックに過程を付ける）

- R11. 「良くない」の報告を送ると、システムはその回答の質問・回答・出典・検索と確認の過程（ステップ）・モデル・時間を、管理者が読める報告として扱う。送る前に、そのことを報告の欄に明示する。
- R12. 失敗・回答なし・取消の通知にも「問題を報告」を置き、同じ報告の欄を開く。理由の選択肢に「エラー・回答が出ない」（`error`）を足す。
- R12a.（T16 で追補）報告の送信が 404（回答が保存されていない）のとき、システムは「この回答は保存されていないため、報告できません。」を出し、そのターンの「問題を報告」を以後出さない。
- R13. 管理者は「フィードバック」の一覧で、報告を新しい順に見られる（評価・理由・コメントの冒頭・質問の冒頭・モデル・回答なしの理由・日時・報告者・状態）。評価・状態で絞れる。
- R14. 管理者が報告を開くと、そのターンの質問・回答・出典・ステップの全記録（会話の画面の「詳細」と同じ表示）・実行の情報を読める。読むだけで、会話は続けられない。
- R15. 管理者は報告を「対応済み」にでき、戻せる。変更は監査ログに残す（`feedback.resolve` / `feedback.reopen`）。
- R16. 管理者は報告の中身を「診断用にコピー」できる（質問・回答・ステップ・実行の情報を 1 つの JSON にしたもの。API キーなどの秘密、利用者のメールアドレスは含めない）。
- R17. 管理者でない利用者は、一覧も他人の報告も読めない（403）。共有リンク（specs/008）にはこれまでどおりステップを出さない。
