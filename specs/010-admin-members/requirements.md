# 010 メンバー管理（P5）— 要件

`docs/handoff.md` P5 の「成员」。完了基準: **owner・admin が利用者の一覧を見て、招待・役割の変更・停止と再開ができる。権限の規則は画面を経由しなくても守られる**。

## 1. 一覧

- R1. `/admin/members` は owner・admin だけが開ける（それ以外は チャットへ戻す）。名前・メール・役割・状態（有効・未確認・停止中）・登録日を出し、名前とメールで絞り込める。
- R2. アカウントのメニュー（サイドバー下部）から owner・admin に「メンバー管理」を出す。

## 2. 操作と権限

- R3. 招待: メールアドレス・名前・役割（member・admin）を入れると利用者を作り、パスワード設定のリンクをメールで送る。招待した人のメールは確認済みとする。既に登録されているメールは断る。
- R4. 役割の変更は member ⇄ admin のみ。owner は画面から作れず、変えられない。
- R5. 規則（サーバで判定する）:
  - 自分自身の役割の変更・停止はできない。
  - owner は対象にできない。
  - admin を対象にする操作（役割の変更・停止・再開）と、admin としての招待は owner だけ。
  - admin は member の招待・停止・再開ができる。
- R6. 停止すると、その人のセッションをすべて失効させ、ログインもできなくする。ただしログイン中の画面はセッションの控え（Cookie、最大 5 分）と API の JWT（最大 15 分）が切れるまで動き続ける。再開で元に戻す。招待のリンク（1 時間有効）は再送できる。
- R7. Better Auth の管理エンドポイント（`/api/auth/admin/*`）をブラウザから直接呼ぶことはできない（403）。管理操作は `/api/admin/members` だけを通す。

## 3. 記録

- R8. 招待・役割の変更・停止・再開をサーバのログに残す（操作者・対象・内容）。監査ログ画面は別の spec で扱う。
