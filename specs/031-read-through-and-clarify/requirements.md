# 031 省略を読み切る・理由の裏付け・聞き返し — 要件

状態: **実装済み（2026-11-19）**。main。

## なぜやるか

2026-11-19 に利用者が見つけた 2 つの会話の失敗:

1. 「Architect-Professional-学習ハンドブック（iPad 版）.pdf この資料の最後の章の内容を教えて」に、「目次は『…ほか 443 節』と省略されているので分からない」と答えた。
   - `get_outline` は先頭の 200 節だけを返し、末尾（最後の章）が見えなかった。続きを読む方法も無かった。
   - 質問に書かれた文書名は、空白と全角の括弧を含むため `named_document_refs` で取り出せず、「指定の文書を読む」が動かなかった。
   - 位置・構成を尋ねる質問（最後の章・目次）は、意味の検索では答えられない。検索の抜粋だけで答えた（別の試しでは試験問題の解説を「最後の章」と答えた）。
   - 同じ `get_outline` を同じ引数で 2 度呼んだ。
2. 「KG-2 はなぜ廃止予定なのですか？」に、「漏れ対策のため KG-5 に変えたから」と答えた。どの資料にもそうは書いていない（手順書第3版は「漏れ対策としてグリスを KG-5 に変更」、部品台帳は「KG-2 廃止予定」とだけ）。最初の下書きは「理由は書かれていない」と正しく答えていたが、調べ残しの見直しで差し戻した結果、別々の資料をつないだ理由になった。利用者が根拠を疑うと、認めかけて同じ主張を言い直した。

利用者からは「あいまいなら聞き返すべきでは」「LangGraph の聞き返し（interrupt）を使うべきでは」との問いもあった。

## 1. 省略を読み切る（ツール）

- R1. `get_outline` は、節が多い文書では先頭と末尾の節を返し、間を「中略」として番号の範囲と読み方を示す。節には 1 からの番号を付ける。
- R2. `get_outline` は `start` を受け取り、その番号の節から続きを返す。
- R3. 文書の中に目次の節（「目次」「Contents」など）があれば、章立ての先頭でそれを案内する。
- R4. 同じツールを同じ引数でターンの中に 2 度呼んだときは、実行せず、上の結果を使うよう返す。省いたことは記録に残す。
- R5. ツールの結果か最初の検索の結果に省略（章立ての中略・`read_document` の打ち切り）があり、下書きが「分からない」と答えているとき、システムは省略された部分を読むよう 1 度だけ差し戻す（確認の種類 `omitted`）。

## 2. 文書名で読む（最初の検索）

- R10. 質問に文書名がそのまま書かれていれば、空白・全角半角・大文字小文字の違いがあっても、その文書を決める。照合は DB で行う（文書が多くても漏らさない）。
- R11. 名前を書かれた文書が長く全部を読めないときは、文書の中の検索に加え、章立ての先頭と末尾（各 20 節）と、目次の節があればその本文（引用できる資料）を最初の検索の結果に添える。

## 3. 理由の裏付け（確認）

- R9. 理由を尋ねる質問では、理由がそのまま書いてある資料だけを根拠にし、別々の資料の事実をつないで理由を作らない（プロンプトと調べ残しの見直しの依頼）。
- R12. 理由を尋ねる質問（なぜ・理由・原因・why）で、引用のある下書きには、補助モデルで「質問の事柄そのものが資料にあるか」「理由がその事柄に結び付けて書かれているか」を確かめ、どちらかが無ければ 1 度だけ差し戻す（確認の種類 `reason`）。確かめたことは結果にかかわらず記録に残す。
- R13. 差し戻した後の書き直しも確かめ、まだ裏付けが無ければ、回答の末尾に「資料にはこの理由はそのまま書かれていない。推測である」と注記する。注記したことは記録に残す。

## 4. 聞き返し

- R6. 「最後の章」のように 2 通りに取れても両方を短く答えられるときは、聞き返さずに両方を答える（プロンプト）。
- R7. 調べても対象が決まらず、どれかで答えがまったく変わるとき、モデルは `ask_user`（問いと 2〜3 個の選択肢）でターンを終えてよい。問いが回答になり、選択肢は続けて聞く候補と同じ部品で出す（見出しは「どれについて答えますか」）。選択肢を押すとその文を次の質問として送る。確認は通さず、続けて聞く候補は作らない。
- R8. 聞き返しは続けて 2 度しない（前のターンが聞き返しなら、このターンは `ask_user` を外して答えさせ、外したことを記録に残す）。雑談と差し戻しの書き直しでも使わせない。
- R14. 質問が「この資料」「その文書」のように文書そのものを指し、添付・範囲・画像・前のターンの引用のどれでも指す先が決まらないとき、システムは最初の検索の後、調べずに聞き返す（グラフの辺「聞き返し」: 最初の検索 → 確定）。選択肢は、利用者が最近登録した文書（2 つまで）と、最初の検索で関連の高かった文書（いちばん高い文書のスコアの半分以上）に、文書名を添えた元の質問。2 つに満たなければ聞き返さない。モデルの `ask_user` と同じく問いで終わるターンとし、記録には理由（`document_unspecified`）を残す。「手順書」のような種類の語は対象にしない（種類で検索すれば両方を答えられる）。

## 5. 画面

- R15. モデルの一覧が届くまで送信できない。届く前に送ると model_id が空になり、サーバーの既定（目録の先頭）で答えてしまい、画面に出ているモデルと食い違う。

## 採らないもの

- **LangGraph の `interrupt`**: 029 の判断のまま。聞き返しは「問いで終わるターン」で書ける。`interrupt` で run を止めて待つと、runner のキュー・取消・再生成に待機中の扱いが要り、出典番号（run ごとの登録）を再開した run に持ち越す仕組みも要る。得るものに見合わない。
- **029 の決定的な聞き返し（版・機種・拠点のメタデータ）**: 入庫側に項目が無い。今回の失敗（章の位置）は調べた後でしか分からないあいまいさなので、モデルが調べた後に使えるツールにした。決定的な判定は、メタデータができたら足す（029 T18 のまま）。

### 追加（2026-11-19）

- R16. 会話に前のターンが無いのに、質問が「この件」「その件」「例の件」や文頭の「それは」「これは」で何かを指し、添付・範囲・画像のどれも無いとき、システムは最初の検索の後、調べずに聞き返す。検索の結果は指す先の手がかりにならないので選択肢は出さず、対象（文書名・設備名・件名など）を添えて聞き直すよう頼む。記録の理由は `reference_unknown`。
- R14 の補足: 「この資料」には、添付の資料・この表・この図・このスライド・本資料・英語の the attached file / this spreadsheet などを含める。関連の高い文書が 1 つしかなくても指す先は決まっていないので、次に関連の高い文書を足して選択肢を 2 つにする。
