# 038 社内システムのツールの審査と定義の固定 — 要件

状態: 承認済み（2026-11-28、利用者の指示）。

## なぜやるか

032 では、MCP サーバが返すツールの説明と読み取り専用の印（`readOnlyHint`）をそのまま信じて、取得したツールを「使う」にしていた。
説明が変わったときはツールを止めていたが、何が変わったかは見えず、止めた理由は接続の誤りの欄に書いていた。

MCP サーバは社外の製品（不信の入力）として扱う。参考にしたのは別のプロジェクト（enterprise-agent-platform）の設計
（architecture.md F.6）: ツールの説明はモデルの文脈にそのまま入る攻撃面（説明に指示を仕込む tool poisoning、審査の後に定義を差し替える rug pull）であり、
サーバが自分で言う「読み取り専用」は安全の根拠にならない。そこで、管理者が 1 つずつ審査し、審査した定義を固定し、
変わったら止めて差分を見せてから審査し直す流れにする。

## 1. 定義の固定

- R1. システムは、ツールの定義（名前・説明・入力の型・読み取り専用の印）の SHA-256（定義の指紋）を、取得するたびに計算して保存する。
- R2. 管理者がツールを審査したとき、システムはそのときの定義（説明・入力の型・印）と指紋を「審査した定義」として保存する。審査した人と時刻も残す。
- R3. ツールの状態は 3 つ: **未審査**（審査した定義が無い）・**審査済み**（今の指紋が審査した指紋と同じ）・**定義が変わった**（違う）。
- R4. 取り直しで、審査済みのツールの指紋が変わったとき、システムはそのツールをエージェントに渡さない。
  管理者の「使う」の選択は残し、審査し直したら元に戻る。変わったことは監査ログ（`mcp.tool.changed`）に残し、管理画面に数を出す。
- R5. 取り直しで新しく見つかったツールは未審査とし、エージェントに渡さない（032 R9 の「新しい読み取り専用のツールは使う」をやめる）。
- R6. 登録の CLI（`mcp-register`）は管理者の確認として扱い、審査したことのあるツールは変わった定義を受け入れ、新しいツールは読み取り専用の印のあるものだけを「読み取り」で審査済みにして使う（印の無いものは未審査のまま）。評価の手順は変えない。

## 2. 審査

- R7. 管理者は、ツールごとに副作用（**読み取り** / **書き込み**）を自分で決める。サーバの読み取り専用の印は参考として並べて出すだけにする。
  印が無いのに「読み取り」にするときは、画面で警告する。
- R8. エージェントに渡せるのは、審査済みで、副作用が「読み取り」で、管理者が「使う」にしたツールだけ（書き込みは 032 のとおり扱わない）。
- R9. 審査の操作は、管理者が見ていた定義の指紋を送る。その間に定義が変わっていたら、システムは審査を受け付けない（409）。
- R10. 審査は監査ログ（`mcp.tool.review`）に残す: ツール・副作用・審査した指紋・前の指紋・説明を書き換えたか・使うか。

## 3. モデルに渡す説明の書き換え

- R11. 管理者は、モデルに渡すツールの説明を書き換えられる（2,000 字まで。空ならサーバの説明）。書き換えた説明は、サーバの説明が変わっても残る。
- R12. エージェントは、書き換えた説明があればそれを、無ければ審査したときのサーバの説明を使う。目録の指紋（`catalog_key`）は、モデルに渡す説明で計算する。

## 4. 画面

- R13. 「社内システム」の管理画面に「システム」「ツール」の切り替えを置く。システムの行には審査待ち（未審査と定義が変わった）の数を出す。
- R14. ツールの一覧: すべてのシステムのツールを 1 つの表で出す（ツール・システム・状態・副作用・サーバの印・説明の書き換え・指紋の頭・使う）。
  語で探せ、状態（すべて・審査待ち・使用中）とシステムで絞れる。行からツールの詳細へ移る。「使う」は表の上で切り替えられる（審査済みで読み取りのときだけ）。
- R15. ツールの詳細: 状態・副作用・サーバの印・今の指紋と審査した指紋・審査した人と時刻・取得の時刻、入力の項目の表（名前・型・必須・説明）、
  サーバの説明の全文、直近の呼び出し（033 R21 の数字から、このツールの分）を出す。
- R16. 定義が変わったとき、詳細は審査した定義と今の定義の差分（説明と入力の型の行ごとの差分・印の変化）を出す。
- R17. 詳細の審査の欄で、副作用・モデルに渡す説明・使うを決め、「この定義を承認」（未審査・変わった）か「保存」（審査済み）で送る。

## 5. 記録

- R18. run の始めに、管理者が「使う」にしているのに定義が変わって渡さなかったツールを、システムの処理（`mcp_held`）として記録する
  （サーバごと 1 行、ツールの名前を並べる）。

## 採らないもの

- **ツールの版の履歴**。審査した定義は最新の 1 つだけ持つ。過去の審査は監査ログで追う。
- **書き込みのツール**。副作用を「書き込み」と決められるだけで、エージェントには渡さない（035 は別の口）。
- **説明の自動の検査（指示に見える文の判定）**。誤検出が多く、審査を人に任せる方針と合わない。差分と全文を見せる。
