# 027 開発の土台（SDD・CI・評価の門）— 要件

## 背景

- 仕様（`specs/`）・テスト・CI（lint / test / gen-check / licenses / compose smoke）はあるが、
  **回答の質は CI で守られていない**。評価は手で回し、比較は都度スクリプトを書いている
  （2026-11-12: 026 の変更で事実網羅は 0.920→0.928 だが、回答不能率が 0.014→0.116 に上がったことを、手作業の比較で初めて知った）。
- 仕様と実装・テストの対応（どの要件をどのテストが守るか）は、人が読んで確かめるしかない。
- 設計は上位のモデル、実装は別のモデル（Opus など）に分ける進め方をするので、**引き継ぎが仕様だけで成り立つ**必要がある。

方針: 仕様 → テスト → 実装 → 評価の門 → 記録、を機械が確かめる。人とモデルは判断に集中する。

## 要件（EARS）

### 仕様（SDD）

- R1 新しい仕様を起こすとき、システムは雛形（`specs/_template/`）から `requirements.md`・`design.md`・`tasks.md` を作れる。
- R2 `requirements.md` の先頭には状態（draft / approved / implemented / superseded）と日付を書く。
- R3 CI は、仕様の形（3 ファイル・状態・要件番号 R<n> の重複なし・`tasks.md` の各項目が要件番号を参照）を検査する。
- R4 CI は、状態が implemented の仕様について、各要件番号を参照するテストが 1 つ以上あることを検査する（テストは `# specs/027 R4` の形で参照する）。無い要件は一覧で示す。
- R5 設計上の判断（採否・理由・却下した案）は `docs/adr/NNNN-*.md` に 1 件 1 ファイルで残す。

### 変更の流れ

- R6 main への変更は pull request を通す。必須の検査が通るまでマージできない。
- R7 PR の本文は雛形に従い、対応する仕様・確かめた方法・評価の結果（エージェント・検索・プロンプトを変えたとき）を書く。
- R8 コミットメッセージが Conventional Commits の形でないとき、CI は失敗する。
- R9 秘密の値（API キーなど）がコミットに含まれるとき、CI は失敗する。

### CI の段

- R10 すべての PR で、速い検査（lint・型・単体・生成物の一致・ライセンス・仕様の検査・秘密の検査）を 10 分以内に終える。
- R11 すべての PR で、結合テストと compose の起動確認を行う。
- R12 `api/src/arag/{agent,search,ingest,prompts}`・`eval/` を変えた PR では、GPU を使わない検索評価を回し、閾値を下回れば失敗する。
- R13 毎晩（と手動で）、実機のモデルで回答評価（harukaze_mix）を回し、基準と比べ、許容を超えて下がれば失敗として知らせる。
- R14 依存に既知の脆弱性が見つかったとき、週次の検査が知らせる。

### 評価

- R15 `arag.eval answer` は、基準（同じ題集・同じモデル）との差を出し、`--gate` で許容を超える低下を失敗にする。
- R16 `arag.eval diff <旧> <新>` は、全体・タグ別の指標と、悪くなった題・良くなった題の一覧を出す。
- R17 評価の結果には、再現に要る情報（git の版・モデル ID・プロンプトのハッシュ・エージェント設定・題集の版）を含める。
- R18 基準は `eval/suites/<題集>/baselines/answer__<モデル>.json` に置き、更新は PR で行う（理由を書く）。
- R19 画面の 👎 の付いた質問は、題の候補（`candidates.yaml`）に書き出せる。

### 手元

- R20 `make check` は、R10 の検査を手元で同じように回す。
- R21 pre-commit は、整形・lint・秘密の検査・コミットメッセージの検査を行う。

### 引き継ぎ

- R22 `AGENTS.md` は、設計と実装を分ける進め方（仕様の状態・誰が何を決めるか・実装側が仕様を変えたいときの手順）を示す。

## 範囲外

- 本番への配備（CD）・イメージの署名。リリースの段（タグ → イメージ → SBOM）は設計だけ示し、実装は後。
- 分散トレース（OpenTelemetry）。ステップの記録で足りている間は入れない。
