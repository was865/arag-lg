# 035 ERP への書き戻し（提案 → 確認 → 1 項目だけ書く）— 要件（草案）

状態: 草案（2026-11-20、specs/033 T17）。承認前。実装しない。

033 で ERP は読むだけにした。ここでは、エージェントが「変えるべき値」を見つけたとき、人が確かめてから
1 項目だけを書き戻す流れを決める。書き込みはエージェントのツールにしない（モデルが勝手に書けない）。

## 1. 提案

- R1. エージェントは書き込みをせず、「提案」（対象・項目・今の値・新しい値・理由・根拠の出典）を回答に添えるだけにする。
- R2. 提案は、決まった種類（最初は「発注の納期の予定」だけ）に限る。それ以外の変更は提案しない。
- R3. 提案は記録（ステップ）に残す。利用者が確かめなかった提案は、何も起こさない。

## 2. 確認

- R4. 画面は提案を確認の札として出し、今の値と新しい値を並べる。利用者が「書き込む」を押したときだけ書く。
- R5. 書く権限は ERP の側で決まる（購買課の利用者だけ。ARag は利用者の身元を渡すだけ）。
- R6. 書く直前に、ERP の今の値が提案のときの値と同じかを確かめ、違えば書かずに知らせる（ほかの人の変更を上書きしない）。

## 3. 書き込み

- R7. 書き込みは ERP の MCP サーバの書き込み専用の口（ツールとしては出さない、`POST /v1/actions/erp/{kind}`）を通し、1 項目だけを書く。
- R8. 書く前の値・書いた値・書いた人・時刻・提案の出典を ERP の MCP サーバの監査ログと ARag の記録の両方に残す。
- R9. 書いた変更は、同じ画面から 1 回だけ元に戻せる（R6 と同じ確かめをして）。

## 入れないもの

- 複数の項目・複数の伝票をまとめて書く変更。
- 発注の作成・取り消し・数量の変更（影響が大きい。必要になったら別の仕様）。
